IA no desenvolvimento, com controle e custo visíveis

O Nexo conduz o trabalho de PM, QA, tech lead e dev do pedido até o PR, usando as IAs já aprovadas. A empresa decide as regras, e a IA não consegue passar por cima delas.

O problema

Adoção sem padrão

Cada pessoa usa a IA do seu jeito. Sem processo comum, o resultado depende de quem está usando.

Controle depois do fato

Revisão e segurança só enxergam o que chega ao PR. Regra escrita em prompt é sugestão, não garantia.

Custo sem dono

É difícil responder quanto cada entrega custou em IA, e se valeu a pena.

Conhecimento que se perde

Contexto, decisões e dependências entre times ficam na cabeça das pessoas.

O que muda

Mudar algo sem saber quem consomeLinhagem entre componentes de times diferentes, sem pedir nada ao GitHub Actions

Por que é seguro aprovar

  • Usa o que já foi aprovado: Claude, Devin e Copilot. Não instala nada de marketplace sem revisão.
  • Dados sob regra: cada classe de dados só vai para o fornecedor permitido. Ferramenta sem bloqueio comprovado não recebe dado confidencial.
  • Trilha de auditoria: quem aprovou o quê, sobre qual conteúdo.
  • Sem código na nuvem do Nexo: o painel recebe métricas, sem prompts, respostas ou código.
  • Kill switch e flags: dá para desligar uma ferramenta durante um incidente, e nenhuma flag desliga o piso de segurança.
  • Sem depender do GitHub Actions: respeita o padrão atual da empresa.

O que pedimos

  1. Uma máquina Windows da empresa, para os testes finais.
  2. Uma conta AWS e a rede interna, com o time do Nexo como responsável pelo serviço.
  3. Dois projetos e um squad-piloto, com uma pessoa de cada papel.
  4. Os aceites de Segurança, Jurídico e LGPD sobre classes de dados e métricas de pessoas.
