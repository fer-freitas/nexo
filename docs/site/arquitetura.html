Arquitetura

O trabalho acontece na máquina de cada pessoa. O GitHub guarda o que é compartilhado, e a AWS recebe só métricas.

Visão geral

Por que assim

DecisãoMotivo
Sem GitHub ActionsA empresa não permite criar nem apagar tarefas no Actions. A validação e a linhagem rodam na máquina de cada pessoa
Repositório do time para as demandasSincroniza entre máquinas sem servidor novo e funciona sem branches órfãos
Central fora do caminho críticoMétrica e painel nunca travam uma entrega
Cérebro por PR e assinadoO agente só lê uma versão revisada, e dá para abrir no Obsidian sem quebrar a assinatura
Portal com HTML do servidorSem JavaScript obrigatório nem CDN, o que evita problemas com proxy e política da empresa
Login atrás de uma portaHoje é por convite. Conectar o SSO é configuração, não redesenho

Módulos

Cada módulo é uma pasta com um manifesto module.yaml, que declara comandos, flags e serviços. Um módulo novo entra sem editar arquivos centrais, e desligar a flag some com o comando. A regra é conferida por teste e pelo import-linter.

Segurança e dados

  • Classe de dados: a data_policy define o que pode ir para cada fornecedor. Devin e Copilot não recebem confidential nem restricted até o bloqueio deles ser provado.
  • Central: recebe ferramenta, modelo, tokens e custo. Prompts, respostas, código e caminhos não saem da máquina.
  • Credenciais: ficam no cofre do sistema, e o agente recebe só o necessário.
  • Conteúdo de terceiros: packs travados por commit e hash. Script dentro de skill é bloqueado por padrão.
