Trackers e status

O estado de cada demanda vive no Nexo. O tracker é opcional: quando ligado, ele recebe cada mudança de estado, e o que alguém mudar à mão no tracker volta para o Nexo.

Os três modos

ModoComo funcionaPara quem
local (padrão)Só o Nexo. O nexo board é o quadroSquads que não usam tracker
githubGitHub Issues, pela API: abre a issue, troca etiquetas e fechaSquads que acompanham pelo GitHub
fileTroca por CSV, sem API: o Nexo exporta no formato de importação e importa o que voltarQualquer outra ferramenta que importe e exporte CSV
nexo config set tracker.kind github --project
nexo config set tracker.github.repo org/repositorio --project
nexo login github
nexo tracker map --check     # confere se todo estado tem de-para

Do Nexo para o tracker

Toda transição de estado no Nexo, como a história entrando em desenvolvimento ou indo para o portão humano, é enviada ao tracker na hora. No GitHub, a issue troca a etiqueta de estado e é fechada quando a demanda termina. No CSV, a linha da demanda é atualizada em .nexo/tracker/outbox.csv.

Se o tracker estiver fora do ar, o trabalho não para: a mudança vai para uma fila e é reenviada no próximo nexo tracker sync.

Do tracker para o Nexo

Quando alguém muda o card à mão, a mudança do tracker prevalece. O Nexo busca essas mudanças antes de rodar uma tarefa ou uma história, e quando você pede:

nexo tracker sync                      # GitHub: reenvia pendências e traz mudanças manuais
nexo tracker import exportado.csv      # CSV: aplica os estados exportados da ferramenta

Uma mudança só é aplicada se o estado externo for diferente do local e do último enviado. Assim, o Nexo não desfaz o que ele mesmo mandou.

As etiquetas do time são preservadas: o Nexo só troca as de estado. Quando a mudança vem do tracker, a etiqueta do Nexo vale mais que o estado aberto ou fechado. Sem etiqueta, uma issue aberta vira "em desenvolvimento" e uma fechada, "concluído".

Ajustar aos nomes da sua ferramenta

Se a ferramenta usa outros nomes de estado ou de tipo, gere um de-para, revise e confira:

nexo tracker map --suggest
nexo tracker map --check

O de-para da squad fica em .nexo/mappings/ no repositório, e o da empresa, em workflows/mappings/ no cérebro. O do repositório vale primeiro.

Para uma ferramenta com API que não seja o GitHub, o caminho é um adaptador novo, com quatro operações: criar, mudar o estado, comentar e buscar o estado atual. Até ele existir, o modo CSV atende.

A sincronização inteira pode ser desligada pela flag tracker_sync, sem nova versão. O trabalho segue só no Nexo.
